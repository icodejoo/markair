## 阶段 Q:F5 手动重载(裁决 #1 的落地,替代自动热重载)

> 裁决 #1 把"`ReadDirectoryChangesW` 监听 + 去抖 + 自动重载"整套砍掉(`src/watch/` 不建),换成一个**成本低一个量级**的手动入口:按 F5 重新走一遍当前文档的打开流程。**它没有 IO 线程、没有目录句柄、没有 overlapped 缓冲,不把"单线程"变成"主线程 + IO 线程"** —— 这正是选它的理由。

| # | 任务 | 要创建/修改的文件 | 验收标准 |
|---|---|---|---|
| **T70** | F5 手动重载当前文档 | 改 `src/shell/window.cpp`(`WM_KEYDOWN` 加 `VK_F5` 分支)、`src/app/main.cpp`(复用已有的打开流程入口);**不新增模块目录** | ① **就是重新走一遍当前文档路径的打开流程**:`WM_KEYDOWN` 收到 `VK_F5`(**不带任何修饰键**;带 `Ctrl`/`Shift` 的组合一律忽略,不做"强制刷新"之类的第二档语义)→ 拿当前文档的完整路径 → 走 **T36 已有的 `WindowState::openDocumentInPlace`** 同一条路径(重新 `file_map` → 重新 `ParseMarkdown` → 重建 `BlockLayoutEngine`),**不要为 F5 另写一条加载路径**;开工前先读一遍 `src/app/main.cpp` 与 `src/shell/navigate.*` 确认这条回调的确切签名与释放顺序。② **滚动位置尝试性恢复,按块下标近似**:重载前记下当前视口顶部的**块下标** `topBlockIdx`,重载后把它钳制到新文档的块数范围内(`min(topBlockIdx, blockCount - 1)`)再滚到该块顶部。**明确不做任何 diff / 最长公共子序列 / 内容指纹匹配** —— 文档被编辑后块下标当然可能偏,但"大致回到刚才那一段"已经满足需求,上一套 diff 算法要多一份新旧文档同时驻留的内存,与本项目的取舍相反;这一点必须写进代码注释,防止后续维护者"优化"成 diff。新文档为空(0 个块)时滚到顶部。③ **降级处理**:文件已被删除 / 被移动 / 被独占锁定导致打开失败时,**保持当前已经渲染的文档内容不变**(绝不清空成白屏),在窗口内用与 M1 既有错误提示相同的形态给一行提示(**不弹 MessageBox**,架构 §9),按 F5 可再试;**因此实现顺序必须是"先成功加载出新文档,再替换旧文档",不得先释放旧文档再加载**。④ **不入历史栈**(见 T65 ②):F5 重载的是同一个文档,不是一次导航。⑤ 零常驻开销:不新增任何成员状态(`topBlockIdx` 是重载过程中的局部变量),`private_bytes` 增量为 0。**验收**:`tests/test_history.cpp` / `tests/test_window_state.cpp` 补纯函数用例覆盖"块下标钳制"(下标 < 新块数、下标 ≥ 新块数、新文档 0 块)与"F5 不改变历史栈";人工验收四条:(a) 外部编辑器改一行后按 F5,内容更新且阅读位置大致不变;(b) 在文档中部按 F5,回到同一段落附近;(c) 删掉文件后按 F5,**窗口内容不消失**、给出提示、不崩溃;(d) 连续按 F5 **100 次**,`PrivateUsage` 无单调上升(沿用 `run_bench.ps1` 的前 5 次均值 vs 后 5 次均值手法) |

## M2 歧义点裁决记录(**用户裁决,2026-09-17**)

> ⚠️ **与 06-m1-tasks.md 文末那一节的性质区别,不要混为一谈**:
> - **M1 的 7 个歧义点**是用户授权"**内存占用为第一目的**"这一原则之后,**由执行方逐条拍板**的 —— 结论的责任在执行方,依据是那条原则。
> - **M2 的这 9 个歧义点**是**用户本人直接给出的裁决**,执行方**没有**拍板权,只负责把结论准确落到任务表里。下面每一条的"依据"是对用户结论的复述与落地说明,**不是执行方的论证**;凡是用户没说的细节(比如去抖取 150 ms、层叠偏移的回卷规则),都按"最省、最不新增状态"的既有工程口径补齐,并在条目里注明是补齐而非裁决。
>
> **9 条全部闭合**。其中 #3/#4(拖放语义 / 拖放技术路径)在 spike 跑完、一度定为"选 `DragAcceptFiles`"之后,又被用户于同一天(2026-09-17)追加裁决**整体推翻**——不做拖放打开这个功能,详见 #3。

### #1 热重载 —— **不做自动热重载,改做 F5 手动重载**(新增 T70)

**裁决**:不做 `ReadDirectoryChangesW` 自动监听 + 去抖 + 自动重载这一整套,**`src/watch/` 目录不建**;但新增一个"手动按 F5 重新加载当前文档"的简单功能。

**依据(用户口径)**:F5 手动重载比自动热重载成本低一个量级 —— 它只是重新走一遍打开流程,不引入常驻 IO 线程、不引入目录句柄与 overlapped 缓冲,**也不把"单线程"变成"主线程 + IO 线程"**(后者才是自动热重载真正昂贵的地方:所有共享状态都要重新审一遍)。

**落地**:
- 新增 **T70**(阶段 Q):`WM_KEYDOWN` 的 `VK_F5` 分支 → 复用 T36 的 `openDocumentInPlace` → 按块下标近似恢复滚动位置 → 文件缺失时保持旧内容并给窗口内提示。
- 文档头部"不做"列表里的"热重载"改写为"**不做自动热重载**",并把 F5 手动重载移进"做"的列表。
- 文档间的矛盾(01 §3/§5.1、03 §2 模块 8 都把自动热重载当 MVP 必备)**随之实际收窄为"降级实现"**:⚠️ **需要用户在收尾时同步修订 01 §3 核心场景 5、01 §5.1、03 §2 的 `watch` 模块行**,否则那三处会与本决策长期不一致(本文档不代改其他文档)。

### #2 文件关联的阶段归属 —— **M2 实现能力 + CLI,M3 只写分发文档**

**裁决**:选项 A。T58~T61 **按原计划在 M2 做**,M3 只把它写进发布文档与 README,**不改动 M2 的任务安排**。

**依据(用户口径)**:04 的 M2 验收标准("干净虚拟机 → 双击打开 → 卸载无残留")必须有落地对象,否则 M2 的验收线整条悬空。`--register` 是裁决 #8(打包形态)的**产物**而非**前置**,两者不冲突。

**落地**:阶段 N 的开工前置警示从"整体受阻塞"改为"T58/T59/T61 可开工";T59 验收标准里删去"归属阶段仍需用户确认"。

**附带问题 A**(文件关联阶段)与 #2 同一问题,同为选项 A,不再单列。

**附带问题 B:关联的扩展名范围 —— 五个全关联**

**裁决**:`.md` / `.markdown` / `.mdown` / `.mkd` / `.mdtext` **全部关联**。

**落地**:
- T58 抽一个 `constexpr` 数组 `kAssociatedExtensions` 作为**唯一定义处**,ProgID 仍**只有一个**(`markair.md`,五个扩展名共用),避免键数翻五倍。
- 注册写入:1 个 ProgID 子树 + **5 条 `<ext>\OpenWithProgids\markair.md`**。
- 卸载清理:删 `markair.md` 整棵子树 + **逐个删掉 5 条 `OpenWithProgids` 值**;只有在"该 `OpenWithProgids` 已空 **且** 该扩展名键是本程序注册时才创建的"两个条件同时成立时才删掉扩展名键本身,**绝不删除注册前就已存在的扩展名键**。
- T59 的 CLI 一次性处理五个,不提供单扩展名子选项;T61 的 `verify_assoc.ps1` 快照与 diff 覆盖五个。

### #3 拖放打开 —— **整体裁掉,不做(推翻了当天更早的"新开进程"裁决)**

**裁决时间线(同一天,2026-09-17,后者覆盖前者)**:
1. 最初裁决 #3:拖放语义定为"新开进程(等同双击)"。
2. 裁决 #4:技术路径先跑 spike。spike 因本机被第三方软件全局注入 shell32 全家桶而无法验证原始问题,只测出"`RegisterDragDrop` 比 `DragAcceptFiles` 多拉约 7.5MB D3D11/DirectComposition 模块"这一条干净结论(`spikes/s04_dragdrop_probe/`)。
3. 用户据此一度拍板选 `DragAcceptFiles`,准备推进实现。
4. **用户随即追加裁决,直接推翻整个功能**:"不支持拖到窗口打开"。

**最终结论**:原 T60(拖放打开)**整条从 M2 任务表移除**,连同 1~3 步的全部子决策(拖放语义、技术路径选型、spike 结论)一并作废,不再是任何后续任务的输入。

**落地**:
- 阶段 N 标题从"文件关联与拖放"改为"文件关联",不含拖放相关任务。
- T65(历史栈)、T70(F5 重载)里原本"与拖放的交互"描述已删除或改写。
- 文档头部"边界"的"不做"列表新增一条"拖放打开",并注明这是对 04 M2 范围的**真实缩减**,需要用户另行确认是否同步修订 `04-delivery-plan.md`(本文档不代改)。
- `spikes/s04_dragdrop_probe/` 的实验代码保留归档,不清理,但不再驱动任何实现决策。
- ⚠️ **遗留的文档不一致**:01 §3 核心场景 3 原文写的是"拖拽一个 `.md` 到已打开的窗口 → 替换当前文档",04 的 M2 范围行也把"拖放打开"列为该做的一项。两处都与"整体不做拖放"的最终结论冲突,**需要用户在收尾时同步修订 01 §3 与 04 的 M2 范围行**,本文档不代改。

### #5 大纲侧栏的布局关系 —— **悬浮覆盖**

**裁决**:悬浮覆盖,**与 M1 查找条同一风格**;**不做挤压、不做 `Relayout`**。

**落地**:T63 改写为"侧栏浮在正文左侧上方,正文视口宽度不变,开关侧栏是纯重绘(严禁 `Relayout`、严禁释放 `IDWriteTextLayout`,口径与 T49 主题切换一致)";浮出条的底色/边框从 T46 `Palette` 的浮出条槽位取,与查找条共用。原"挤压"分支的讨论已删除,只保留一句备选说明(挤压需要额外触发全量 `Relayout`,故未选)。

### #6 大纲侧栏的阅读位置高亮 —— **做,但只在滚动停止后更新(去抖 100~200 ms)**

**裁决**:选项 B。做高亮,**滚动过程中不更新**,滚动停止后去抖 100~200 ms 再更新。

**落地(T63 新增的实现要点)**:
- 状态只有一个 `u32 currentItem`(4 字节),不新增任何数组。
- 定位用**二分查找**(在 T62 已有的、按块下标天然有序的标题数组上),O(log n),不许线性扫描。
- 去抖:滚动事件只重置一个 `SetTimer`,**150 ms**(取用户给的 100~200 ms 区间中值,抽成常量 `kOutlineHighlightDebounceMs` —— *这个具体数值是执行方在用户区间内补齐的,不是用户指定的*);定时器到点才算 + 才重绘。
- **局部重绘**:只 `InvalidateRect` 侧栏矩形(乃至只有新旧两行),绝不整窗失效。
- 侧栏关闭时定时器不注册、状态不存在。
- **量化验收**:侧栏开/关两种状态下各在 300 条标题文档上滚动 10 秒,比较帧耗时分布 —— **P95 ≤ 16.6 ms、掉帧 0、两者中位数差 ≤ 0.5 ms**,以此证明 60 FPS 滚动确实没被拖累(01 §4 的硬指标不许因这条新增行为退让)。
- `Palette` 新增"当前条目底色 + 前景色"两个槽位(light/dark 各一份)。

### #7 `state.ini` 写盘策略 —— **读-改-写 + 文件锁/互斥体**

**裁决**:选项 C。写盘走"**读-改-写 + 命名互斥体**",并**复用项目已有的命名互斥体基础设施**(当前用于"同文件重复双击"的前置判断)。

**落地(T55)**:`SaveAppSettings` 内部:取命名互斥体(超时 ≤ 2 s,超时即放弃本次写盘并静默返回,**绝不无限等**)→ 重读磁盘当前内容 → 只替换本进程改动过的键、保留其余全部键 → 写 `state.ini.tmp` → `MoveFileExW` 原子替换 → 释放互斥体。写盘触发点为设置变更时(主题 / 缩放 / 窗口矩形)+ 进程退出前兜底一次;**窗口移动/缩放必须去抖 500 ms**,否则拖一次窗口会写几十次盘。单测新增"另一进程改了别的键 → 合并后两边改动都在"与"互斥体超时不写出半截文件"两条。

*(执行方补齐、非用户指定的细节:2 s 超时、500 ms 去抖。若用户对这两个数值有偏好,改一个常量即可。)*

### #8 窗口状态记忆的粒度 —— **全局一份 + 层叠偏移**

**裁决**:选项 C。`state.ini` 里只有全局一份窗口矩形;新窗口默认出现在上次位置,**多开时逐个右下偏移 24 px**。

**落地(T56)**:5 个键(`win_x`/`win_y`/`win_w`/`win_h`/`win_maximized`);新窗口若发现同位置已有本程序窗口(`FindWindowExW` 按窗口类名枚举,**不新增任何跨进程共享状态**),按 `kCascadeOffsetDip = 24` 层叠,碰到工作区右/下边界时回卷到起始位置。原"按文件一份"分支的讨论已从任务表删除,只保留一句备选说明:**评估过按文件一份,因需要一张会无限增长的记录表 + LRU 淘汰,使 `state.ini` 从 < 1 KB 膨胀到几 KB,违反架构 §6 的约束而不选**。层叠偏移新增 3 条单测 + 一条"连开 5 个窗口都点得到"的人工验收。

*(执行方补齐:回卷规则与"同位判定"的实现手段;用户只指定了"逐个右下偏移 24px"。)*

### #9 高对比度模式 —— **不处理,但在文档里如实注明**

**裁决**:选项 A(不处理),**但必须在 README / 文档里如实注明"暂不支持高对比度模式"**,不能默默不做。

**落地**:
- 不新增第三套运行期填充的 `Palette`,不接 `SPI_GETHIGHCONTRAST`、不响应 `WM_THEMECHANGED` 的高对比度分支,代码零增量。
- **文档义务**:`README.md`(以及 01/04 的能力描述处)明写一句"暂不支持 Windows 高对比度模式";T68 人工清单新增第 ⑦ 项,要求开启系统高对比度后截一张实际观感图存档,作为将来是否补做的依据。
- 风险表新增一条"高对比度用户拿到不可用的软件而文档里没说",防线就是上面这句声明。
